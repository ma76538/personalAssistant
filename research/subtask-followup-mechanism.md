# 任務子項目與跟進機制

## 核心原則

系統不應自動拆解使用者現有任務。子項目是可選機制，只在使用者明確按「拆解」或「新增子項目」後才寫入。

預設採用「下一步制」：

- 單步任務保留原狀，不硬拆。
- 多步任務先定完成標準，再建立下一個可執行動作。
- 項目任務可逐步累積子項目，但每次跟進仍聚焦當前下一步。

## 任務類型

- 單步任務：30 分鐘內可完成、無依賴、完成標準清楚。
- 多步任務：需要多於一次工作段，或涉及資料、溝通、等待、提交。
- 項目任務：跨數日、涉及多人、完成標準模糊或有外部交付。

## 跟進規則

- 完成一個子項目，不代表母任務完成。
- 母任務完成前，要檢查是否仍有未完成子項目。
- 子項目卡住時，電子秘書應把下一步拆得更細，而不是單純延後。
- 子項目主要服務於推進，不一定全部進四象限或甘特圖。

## 介面規則

- 四象限任務卡只顯示「子頁面」入口和子項目摘要，不直接承載大量拆解操作。
- 每個四象限任務都有獨立子頁面，用來查看、新增、勾選完成子項目。
- 子頁面 checkbox 只改子項目完成狀態，不自動把母任務標為完成。
- 子頁面第一版只提供手動新增子項目，不放 LLM 拆解入口，避免干擾任務內容。
- 建立子頁面機制不等於拆解現有任務；資料庫不應因此新增任何既有任務的子項目。

## 經驗沉澱

常見任務可累積成拆解規則：

- 申請/提交類：確認文件 → 收集文件 → 提交 → 跟進結果。
- 合作洽談類：列目標 → 準備資料 → 約時間/溝通 → 會後跟進。
- 開發類：定義驗收成果 → 實作下一步 → 測試 → 記錄卡點並再拆下一步。
- 寫作/文件類：列大綱 → 找素材 → 寫第一版 → 檢查和提交。
