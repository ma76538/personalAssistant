# LLM 任務梳理、提醒與經驗沉澱

## 核心問題

這份文件回答「如何透過 LLM 幫我梳理工作、提醒，並將工作邏輯變成 Markdown 經驗累積下來」。

LLM 不應直接決定資料庫狀態，也不應自動替使用者承諾時間。它的角色是幫忙理解、追問、提出排序建議、拆下一步、總結經驗；真正改任務、改排程、改提醒前，仍要經過系統規則或使用者確認。

## LLM 在任務梳理中的角色

LLM 應負責把零散輸入轉成可判斷的任務資料：

- 任務名稱：這件事到底要交付甚麼。
- deadline：有沒有外部後果，屬於 hard deadline 還是 soft deadline。
- 估計工時：是 2 分鐘小事、30 分鐘任務，還是需要拆解的長項目。
- 價值分：這件事是否有 PO、金主、公司方向、長期累積價值。
- 四象限建議：根據重要和緊急兩條軸提出建議，而不是只看使用者原本放在哪個 list。
- 依賴關係：哪些任務必須先完成，哪些任務完成後會自然觸發下一步。
- 缺失資料：如果無法判斷，LLM 應提出最少量關鍵問題，而不是亂估。

LLM 的輸出應是 preview：

```text
我理解這件事是：
任務：準備某項申請文件
建議分類：緊急重要
原因：hard deadline 在 3 日內，且外部提交有後果
下一步：先整理需要提交的文件清單，60 分鐘
需要確認：deadline 是否真的不能延後？
```

使用者確認後，系統才更新任務、四象限、下一步或排程。

## 工作先後次序判斷

LLM 判斷先後次序時不應只問「哪個最急」，而應同時看五個因素：

- Deadline 壓力：已過期、3 日內到期、或剩餘工時已超過可用工作容量。
- 外部後果：客戶、政府、合約、比賽、會議材料、他人等待。
- 公司價值：是否直接支持大健康、展品設備、電子秘書 MVP 或有明確商業價值。
- 依賴關係：A 未完成會否令 B 無法開始。
- 任務大小：長任務要拆成 60-90 分鐘下一步，不能只整個放入排程。

建議排序格式：

```text
1. 今日主任務：最高 deadline 風險或最大外部後果
2. 今日副任務：第二高風險，至少取得保底進度
3. 可順手清理：2 分鐘或低能量小事
4. 暫不處理：無 deadline、低價值、未有下一步的項目
```

如果緊急重要任務多於每日可用時間，LLM 不應把所有事都排進今日，而應要求取捨：

- 縮小 scope
- 委派
- 改 deadline
- 拆更小下一步
- 取消或移出緊急重要

## 提醒邏輯

LLM 不負責逐分鐘判斷是否發送提醒，這仍由 deterministic reminder tick 執行。LLM 負責決定提醒文字、追問策略和下一步建議。

提醒應分成三類：

- 開始提醒：提醒使用者現在要開始哪一件緊急重要任務。
- 進度追問：任務進行中或到預計結束時間，追問完成、卡住或延後。
- 風險提醒：任務多次延後、deadline 壓力上升、或今日容量不足時，要求使用者作取捨。

LLM 回覆不應只說「請繼續努力」，而要幫使用者做決策：

```text
這件事已延後 2 次，且 deadline 前只剩 2 個可用工作時段。
建議你現在選一個：
1. 立即做 60 分鐘
2. 只完成最小可交付版本
3. 改 deadline / 通知對方
4. 取消或降級
```

## Markdown 經驗庫

每次 LLM 做出有效判斷後，系統應能把「判斷邏輯」沉澱到 Markdown，而不是只留在聊天記錄。

建議建立 `research/experience/` 作為經驗庫，每個主題一份 Markdown：

```text
research/experience/
  priority-rules.md
  reminder-rules.md
  project-breakdown-rules.md
  user-preferences.md
```

每條經驗應包含：

- 場景：甚麼情況下適用。
- 判斷：當時怎樣分類或排序。
- 原因：為甚麼這樣判斷。
- 結果：後來是否有效。
- 更新日期：方便日後修正。

範例：

```markdown
## 規則：有外部提交後果的任務優先看 deadline

- 場景：政府、客戶、比賽、合約、會議前材料。
- 判斷：deadlineType 應標為 hard。
- 排序：若 3 日內到期，進入緊急重要。
- 提醒：至少提前一天及當日提醒。
- 結果：待驗證。
- 更新：2026-06-20
```

## 實作原則

- LLM 建議不直接寫入資料庫，先進 preview。
- Markdown 經驗不等於硬編碼規則；它是 LLM prompt 和日後系統規則的素材。
- 當同一類判斷重複出現 3 次且結果有效，才考慮把它升級為程式規則。
- 經驗庫要保留「為甚麼」，否則日後很難修正。

## 後續功能建議

- 加入「AI 梳理」按鈕：輸出任務排序、依賴關係、缺失問題和今日建議。
- 加入「保存為經驗」按鈕：把本次判斷摘要寫入 Markdown 草稿。
- 每週整理一次經驗庫：LLM 找出重複規則、矛盾規則和已過時規則。
- 日後接入甘特圖時，用依賴關係和下一步資料生成更合理的任務鏈。
