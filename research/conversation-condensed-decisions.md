# 對話壓縮版決策紀錄

本文是截至 2026-06-20 的對話壓縮版，目的是把已確認的產品方向、功能邏輯和衝突解法沉澱成可繼續開發的規格來源。

## 核心目標

個人排程助理要解決三件事：

1. 知道使用者要做什麼。
2. 判斷工作的先後緩急和優先度。
3. 在適當時間提醒每日真正要做的事，避免漏事。

第一版採用本機常駐系統：

- Dashboard 作為整理、編輯和查看任務的後台。
- Apple Reminders 作為任務入口，方便 Siri 快速新增。
- Telegram 作為提醒和確認渠道。
- MiniMax LLM 負責中文理解、任務抽取、排序建議和摘要。
- SQLite 作為本地資料庫。
- Calendar 只讀，用作活動/忙碌時間參考，不把任務時間塊寫入 Calendar。

## 任務分類

### 主分類

保留四象限作為主要分類和操作語言：

- 緊急重要
- 緊急不重要
- 不緊急重要
- 不緊急不重要

系統內部用「緊急」和「重要」兩條軸計算象限。

### 待定

`待定` 是任務入口和暫存區，不屬於四象限。

使用場景：

- Siri 或 Reminders 快速記低，但還未知道何時做。
- 不想立即判斷緊急/重要。
- 需要日後整理、補 deadline、補價值判斷。

待定任務不進入甘特圖和排程。它應放在四象限下方、甘特圖上方，空間要壓縮，避免干擾主工作區。

### 2 分鐘完成

`2 分鐘完成` 是可以立即完成、且約 2 分鐘內完成的任務。

它不是「以後某一刻做但只需 1 分鐘」的容器。若任務未到時間才做，應留在 Reminders 或待定，待到時間前再提醒或整理。

2 分鐘任務放在頁面最上方，只保留完成操作；按完成後進入完成箱。2 分鐘任務不應同時出現在四象限。

## 優先級和排程原則

### 每個項目原則上要有 deadline

需要排程、提醒或被判斷為緊急的任務必須有 due date。若拖入緊急象限但沒有 due date，Dashboard 要高亮提醒補回。

待定任務可以暫時沒有 due date，因為它尚未進入正式排程。

### 長任務

很多工作不是一次完成，因此長任務要拆成：

- 項目：保存目標、價值分、deadline 類型、總進度。
- 下一步：60-90 分鐘可執行工作，才進入排程和提醒。

完成一段工作後，系統應追問：

- 完成了什麼。
- 是否卡住。
- 下一步是什麼。
- 是否需要重排未開始任務。

### 多個緊急重要任務

若緊急重要多於一個，不應只按使用者感覺排序，而要用以下順序分配：

1. Hard deadline 最早者優先。
2. 外部承諾/客戶/政府/合約/比賽風險較高者優先。
3. 剩餘可用時間不足以完成者提前處理。
4. 價值分較高者優先。
5. 已被推遲多次者提高權重，避免永遠延後。

排程器只重排未開始任務，不移動進行中、完成或取消任務。

## Dashboard 最終方向

首頁順序應為：

1. 今日先做
2. 2 分鐘完成
3. 四象限
4. 待定
5. 甘特圖
6. 每月日曆
7. 日曆連接設定
8. 完成箱
9. 提醒設定

左方菜單應對應上述主要區塊，不顯示未實作或暫時不用的入口，例如標籤、專案、統計報告。

新增任務表單保留：

- 任務標題
- 分類：待定、2 分鐘完成、四象限
- Start date
- Due date
- 價值分
- Deadline 類型
- 長項目/所屬項目/進度備註

已移除或弱化：

- 工時、優先級和狀態在新增任務時不要求使用者填。
- 工作類型和情境先移除，因語意不清。
- 頂部搜尋任務、手動同步 Todo、建議安排先移除。
- 統計數字先移除。

## Reminders 同步

Reminders 是任務入口和同步 source of truth。

同步範圍只包含：

- 待定
- 緊急重要
- 緊急不重要
- 不緊急重要
- 不緊急不重要

其他 Reminders list 不同步入系統。

同步規則：

- Reminders 新增或更新：本地新增/更新。
- Reminders 完成：本地改為完成，移入完成箱。
- Reminders 刪除或移出同步範圍：本地硬刪除。
- Dashboard 完成或修改任務：要寫回 Reminders。
- Dashboard 的待定、進行中、完成狀態要寫入 Reminders 標籤。

## Calendar

Calendar 和 Reminders 分工不同：

- Reminders 是任務入口。
- Calendar 是活動、會議、固定時間點和忙碌時間來源。

Calendar 第一版只讀，不寫入任務 focus block。月曆顯示任務時，任務應按 due date 放入月曆。

`kevin@region.mo` 目前透過 macOS Calendar / EventKit 橋接讀取。直接 Google OAuth 尚未完成，後台只先保存電郵和說明狀態。

## 提醒策略

提醒要像秘書，但不能把所有事情都變成噪音。

已確認方向：

- Telegram 每日主要提醒緊急重要事項。
- 提醒設定放在 Dashboard，可調整開始前、開始時、間歇、結束、逾期、夜間低打擾。
- 待定任務每日集中整理，不即時連續打擾。
- 高優先級任務可以更頻密提醒，但夜間仍受低打擾限制。

## LLM 角色

LLM 不直接寫資料庫狀態。它負責：

- 從中文輸入抽取任務、期限、估計工時、價值、deadline 類型。
- 判斷是否是長項目。
- 建議四象限和下一步。
- 在使用者完成/卡住/延後時提出下一步建議。
- 把每次決策和經驗沉澱成 Markdown，累積成日後可編程的 skills。

真正新增、修改、重排前仍需要 preview / confirm。

## 已確認不做或暫緩

- 暫時不新增「到時提醒區」。
- Calendar 暫時不寫入任務時間塊。
- WhatsApp 暫不實作，先以 Telegram 為唯一通知渠道。
- 標籤和專案入口暫時隱藏。
- 直接 Google OAuth 暫緩，先透過 macOS Calendar 讀 `kevin@region.mo`。

## 衝突檢查結果

已解決的衝突：

- 「只同步四象限」與「加入待定列表」衝突：最終同步範圍改為 `待定 + 四象限`，四象限外其他列表仍不同步。
- 「2 分鐘任務是否出現在四象限」衝突：最終為獨立區，不重複出現在四象限。
- 「到時提醒區」曾提出又取消：最終不新增。
- 「Calendar 是否寫入任務」與「Calendar 只放活動」衝突：最終只讀 Calendar，不寫入任務。
- 「統計數字」曾要求美化，後來要求移除：最終先移除統計數字。
- 「今日時間線」語意不清：最終移除，以「今日先做」和月曆取代。

目前仍需後續落實或驗證：

- `kevin@region.mo` 的直接 Google OAuth。
- Dashboard 修改任務後寫回 Reminders 的完整可靠性。
- LLM 經驗沉澱為 skills 的具體檔案格式。
- 長項目拆下一步與甘特圖排程的完整閉環。
